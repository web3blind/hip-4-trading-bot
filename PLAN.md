## Module contract and assumptions
1. Module is inactive by default. Public monitoring and observation do not call signing, cancellation or transfers. Observation records proposed quotes and book snapshots, NOT invented fills, PnL or reward earnings.
2. First strategy is deliberately bounded passive book quoting, not a model of fair probability: best bid/ask within an owner-approved price corridor and spread requirements. No underlying-price model, automatic market selection, expiry-rollover, or aggressive IOC/GTC fallback. Maker orders MUST use ALO/post-only through a dedicated additive client path, preserving current Limit/Market behavior.
3. One outcome coin per session, one active live session per account/network initially; no leverage/short selling. Market expiry must be known, enough time must remain, quote token USDC. Reject short-expiry price binaries for the initial live strategy; observation remains available. No automatic cross-market expansion.
4. Owner reviews/approves immutable account+network+coin+mode, expiry/duration, cumulative buy-spend cap (fees/reserves included, no recycling sale proceeds into unlimited turnover), inventory cap, order size, price corridor, spread threshold, order/action cap, and loss-stop settings. UI explains loss stop is not a guaranteed maximum loss; inventory can become worthless. Parameters must have explicit units and bounded validation. Session cannot extend/raise limits without a new Telegram approval.
5. MCP can propose a session and read its status/evidence. Only private owner Telegram confirmation creates a live grant. MCP read credentials never mutate sessions or place/cancel orders. Existing MCP trading methods still require per-action approval; no generic session bypass. A trade credential may request stop/revoke of its scoped session; cancellation authority is limited to recorded session orders and survives grant expiry for cleanup only. Key revocation invalidates grants from that credential.
6. Session state and per-action intents are durable before exchange writes, with CLOIDs and order ownership. Unknown submission/cancel results block replacement and reconcile rather than retry. Partial fills, fees, stale/missing API responses and capped history must not turn into assumed zero exposure. Show unresolved state clearly. Hard per-session bounds and non-overlap/reentrancy protection.
7. Only zero initial target inventory and no foreign target orders/active bundle attribution may start a live session. Sell only shares proven bought by that session. Never use existing bundle/ordinary inventory. Detect outside activity/inventory mismatch and suspend rather than commandeer holdings. Never cancel-all, never sell to flatten on stop. Ordinary manual flows stay intact; reuse the existing runtime lock only during bounded financial execution.
8. Restart does not silently resume new quoting: reconcile/cancel previously owned outstanding orders, keep grants paused/recovery-required until fresh owner approval. Account/network switch must not orphan old live orders: cleanup using the original client before releasing it, or refuse transition if unresolved (only when a liquidity session exists). Inactive module performs no exchange calls and must not affect legacy lifecycle.
9. Stop/revoke/expiry/risk trigger forbids new placements and attempts cancellation of OWN recorded orders only. No guaranteed offline cancellation: surface unresolved cleanup if the exchange is unavailable. Do not mark session fully stopped while own orders are unconfirmed. Remaining acquired inventory stays visible, no automatic liquidation.
10. Rewards are public campaign amounts/history, separate from account eligibility and credited wallet payouts. Show source freshness/unavailable states, not zero/default rewards. Monitoring deltas deduplicated; no assumption that builder code guarantees qualification. Provider contract is under live-source discovery before implementation.

## Data safety
- Protect existing `.env`, encrypted `data/config.json`, runtime lock/socket, account-scoped cache SQLite/WAL/SHM, order/bundle histories and logs. No tests open real data paths.
- Module-owned persistent storage must be account/network scoped under DATA_DIR and use the same restrictive permissions and isolated test-data convention. No changes to existing economic records.
- No `reset`, `clean`, broad sync, migrations against production, service launch or signed network calls. If later deploying, fresh read-only inventory, encrypted verified backup including module state, pre-deploy independent review and retained-record checks are mandatory.
